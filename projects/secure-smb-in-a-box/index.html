Secure SMB in a Box.

A hardened small-business network built on one server and one managed switch, documented step by step so anyone can rebuild it, break it, and learn from it.

View on GitHub Book a consultation
The idea

What a small business actually needs.

Most small offices run on an ISP modem, one flat network, and backups nobody has tested. This project builds the opposite on a home lab: a segmented, monitored, recoverable network that mirrors the work MaZen does for clients.

Every phase ends with a verification checklist and a “break it” exercise, so the evidence shows the controls work, not just that they were installed.

What it covers

The stack.

  • OPNsense firewall with five VLANs and default-deny rules between them
  • Active Directory with baseline Group Policy
  • Wazuh monitoring for endpoints and firewall logs
  • Proxmox Backup Server with a tested restore
  • Greenbone vulnerability scans, with before and after results
  • A purple-team exercise: attack, detect, harden
The build

Six phases, each documented.

Phase 1 · In progress

Network and firewall

OPNsense routes and filters the VLANs while the switch stays layer 2 only.

 Phase 2 · Planned

Identity

A small Active Directory domain with realistic users, groups, and policy.

 Phase 3 · Planned

Monitoring

Wazuh agents and firewall logs feeding alerts you can act on.

 Phase 4 · Planned

Backups and restore

Encrypted backups, plus a recorded restore test with timings.

 Phase 5 · Planned

Vulnerability management

Scan, prioritize, fix, and rescan to prove the risk went down.

 Phase 6 · Planned

Purple-team exercise

Controlled attacks mapped to MITRE ATT&CK, with detection gaps found and closed.
How it was built

The approach.

  1. Plan. Define the VLANs, rules, and success checks before touching the hardware.
  2. Build. Snapshot, change one thing, and test it.
  3. Prove. Run the checklist and keep the evidence.
  4. Break and fix. Fail on purpose to confirm the controls and the recovery path.
Why it matters to clients

Lab work, client-ready habits.

The same discipline applies to client projects: segmentation by default, monitoring that is actually watched, and backups that have been restored at least once. A sample client report template is included in the repository.

All addresses and credentials in the public repository are placeholders. Nothing from a real client network is published.
